# confluence-sync

**Confluence Cloud ↔ Markdown 가져오기(Pull)·업로드(Push) CLI**

- **push** — 로컬 `.md` 디렉토리를 Confluence 페이지 트리로 발행. 폴더 구조가 그대로 페이지 계층이 됩니다.
- **fetch** — 저장된 스코프의 연결된 페이지 변경 여부만 확인. 문서와 동기화 기준은 유지합니다.
- **pull** — Confluence 페이지·폴더·**스페이스 전체**를 읽어 `.md` 로 가져옵니다.

문서를 git으로 관리하면서(docs-as-code) Confluence를 미러로 두거나, 반대로 Confluence에 쌓인 문서를 마크다운으로 내려받아 쓸 수 있습니다.

**[Obsidian](#obsidian) vault 와 그대로 맞물립니다** — pull 한 문서는 내부 링크가 이어져 그래프 뷰가 동작하고, vault 에서 쓴 `[[wikilink]]`·`![[embed]]`·frontmatter 를 push 가 그대로 이해합니다.

Push는 업로드 전에 `convert --to markdown`과 같은 전처리를 내부적으로 수행합니다. 위키링크·이미지 참조·각주를 변환하고 PDF의 `#page=N` 참조는 해당 페이지의 PNG로 만듭니다. CLI `push --dry-run`과 웹 업로드 미리보기도 같은 결과를 계산합니다. 원본 문서·첨부 경로는 유지하고 임시 파일은 성공·실패 시 모두 정리합니다. 변환 실패는 원격 변경 전에 중단합니다. 별도의 Markdown 변환본을 만들지 않고 Vault를 기준 폴더로 사용할 수 있으며, 해당 폴더의 연결 설정·스코프·매핑은 따로 준비해야 합니다. 오류 보정(`convert --fix`)은 자동 적용하지 않습니다.

옵시디언 콜아웃(`> [!summary]`, `> [!info]`, `> [!warning]`, `> [!danger]` 등)은 업로드 시 제목과 종류별 색상이 있는 Confluence 패널로 렌더링합니다. 본문의 링크·이미지·목록·표와 중첩 콜아웃을 지원하고 로컬 문서 미리보기에도 표시합니다. 접힘 기호(`+`·`-`)는 제거하고 본문은 펼쳐 표시합니다. 일반 인용문과 코드 예제는 유지하며 원본 `.md`는 변경하지 않습니다.

## 원격 변경 확인 (Fetch)

```bash
csync fetch                    # 현재 작업공간의 저장된 스코프
csync fetch --base ./스페이스   # 기준 폴더 지정
```

페이지별로 호출하지 않고 **매핑된 페이지 ID를 100개씩 묶어** 버전·제목·부모 위치를 조회합니다. 본문과 첨부파일은 다운로드하지 않습니다. 결과는 `.csync/remote.json`에 저장하고 **2분 동안 캐시를 재사용**하며 조회 시각과 이번 API 요청 횟수를 표시합니다. 스코프·매핑·계정·연결 설정이 바뀌면 캐시를 다시 조회합니다. 한 실행은 최대 20회 요청으로 제한하고, 실패·제한 초과 시 기존 캐시를 유지합니다.

결과는 `버전 동일`, `원격 변경`, `조회 불가`, `확인 필요`로 구분합니다. 조회 결과에 없는 페이지를 삭제로 단정하지 않습니다. 새 원격 문서·폴더·첨부 단독 변경은 검사하지 않으며, 새 문서 발견이나 실제 내용 반영은 Pull이 담당합니다. `버전 동일`도 검사 시점의 페이지 메타데이터 비교 결과이며 전체 상태 일치를 보장하지 않습니다.

Fetch는 문서와 `.csync/mapping.json`의 **기준 버전·해시를 변경하지 않습니다.** Push 충돌 검증이나 업로드 미리보기를 대신하지 않습니다. 웹에서는 문서 미리보기 아래의 독립된 **.env 연결 설정** 영역에서 연결 정보를 불러오고 스코프를 저장한 뒤, 하단 실행 영역의 **원격 변경 확인(Fetch)**을 누르면 같은 CLI 명령으로 실행합니다. Push·Pull과 같은 위치에 있으며 실행 후 바로 아래의 03 실행 내역으로 이동해 결과를 확인합니다. 자동 반복 조회는 하지 않습니다.

## v2: 스페이스 루트 연결과 필수 작업 스코프

**기준 폴더는 스페이스 전체의 로컬 루트**, **스코프는 그 안에서 이번에 Push·Pull할 파일 또는 폴더**입니다. 스코프는 원격 부모 위치를 바꾸는 설정이 아닙니다. 기본값 없이 사용자가 직접 선택하며, 전체는 `/`입니다.

```bash
csync init --base ./스페이스 --scope /      # 처음 전체 Pull할 범위
csync pull --base ./스페이스
csync init --base ./스페이스 --scope "지식자산/특허출원"
csync push --base ./스페이스 --dry-run --verify
csync push --base ./스페이스
# 파일 하나만 작업하려면 파일 자체를 지정합니다.
csync init --base ./스페이스 --scope "지식자산/특허출원/006_변리사_전달_문서.md"
csync push --base ./스페이스
```

- 파일 스코프는 그 문서 하나, 폴더 스코프는 하위 문서 전체에 적용됩니다. Push와 Pull이 같은 범위를 사용합니다.
- 기준 폴더 밖의 경로는 거부합니다. 별도 `_백업` 폴더의 문서를 쓰려면 그 폴더를 기준 폴더로 선택해야 합니다.
- 범위 밖 문서·첨부·매핑은 유지하고 동기화 대상에서 제외합니다. 스코프 변경만으로 원격 문서를 이동하거나 매핑을 제거하지 않습니다.
- 최초 연결 때 스페이스 홈페이지를 확인합니다. 이후 범위 변경은 로컬 경로만 검증하며 전체 매핑을 원격 조회하지 않습니다.
- 처음 빈 폴더에 Pull할 때는 `/`를 선택합니다. 부분 Pull은 기존 매핑의 페이지 ID를 이용해 원래 로컬 위치에 저장하며, 매핑이 없는 부분 범위는 추측하지 않습니다.
- `CONFLUENCE_PARENT_ID`는 사용하지 않습니다. 이전 원격 연결 스코프 설정은 자동으로 작업 범위로 간주하지 않으며 `init --scope`로 다시 선택해야 합니다.

### 상태 파일 보관과 기존 파일 이전

`.env`는 기존 위치에 두고 csync가 관리하는 파일은 `.csync/` 안에 모읍니다. 문서 경로와 매핑 키의 기준은 계속 작업공간 루트이며 `.csync/`로 바뀌지 않습니다.

```text
문서 루트/
  .env
  .csync/
    mapping.json
    workspace.json
    ignore             # 선택: 제외 규칙
  README.md
  지식자산/
```

기존 루트의 `.confluence-sync.json`, `.confluence-workspace.json`, `.confluence-syncignore`도 계속 읽고 같은 위치에 저장합니다. 기존 파일을 모으려면 다음 명령을 명시적으로 실행하세요.

```bash
csync init --migrate --base . --dry-run
csync init --migrate --base .
```

매핑 ID·해시·원격 버전·이동 대기·관리 범위와 제외 규칙의 내용을 그대로 복사하고 검증한 뒤 기존 파일을 제거합니다. `.env`와 문서·첨부는 이동하지 않으며 Confluence 호출도 없습니다. 양쪽 위치의 파일 내용이 다르면 덮어쓰지 않고 중단합니다. 중첩된 다른 작업공간은 이전하지 않습니다. 명시적인 `--mapping <path>` 경로는 계속 지원하며 자동 이전 대상이 아닙니다.

### v1에서 이전할 때

1. 문서·첨부·매핑·`.env`를 백업하고 미저장 로컬 변경을 별도로 보관합니다. 메타데이터 위치를 옮기려면 위 `init --migrate`를 사용합니다.
2. `csync init --base <실제 문서 루트> --scope <로컬 파일·폴더>`로 로컬 작업 범위를 직접 선택합니다. 예전 `syncPaths`·`root`·부모 환경변수는 자동 선택에 사용하지 않습니다. 스코프 변경은 로컬 범위만 저장합니다. 전체 매핑은 유지하며 범위 밖 문서는 제외합니다.
3. **예전 매핑에는 `remoteVersion`이 없어 변경 업로드를 차단합니다.** 기존 해시와 로컬 내용이 같은 문서를 pull하면 원격 버전과 새 기준을 확보합니다. 변경 파일을 먼저 덮어쓰는 방식의 초기화 옵션은 제공하지 않습니다.
4. 예전 `pull --space` 결과가 `<출력>/<스페이스>/`에 있고 매핑은 출력 바깥 기준이라면, 새 빈 `--out`에 받아 구조를 비교하세요. 기존 경로·설정을 자동 이동하거나 매핑을 추측해 재작성하지 않습니다. 이미 수동 보정한 문서 루트는 그대로 사용합니다.
5. 하위에 별도 `.env`·매핑을 만든 기존 작업공간은 독립적으로 유지합니다. 자동 병합하지 않으므로 해당 하위 폴더를 `--base`로 지정해 사용할 수 있습니다. 새로 구성하는 작업공간에서는 루트 하나에 관리 범위를 설정하면 됩니다.

부분 Pull은 전체 매핑을 확보한 기준 폴더에서 로컬 파일·폴더 스코프를 선택해 실행하세요. v1의 `pull --root`·`--no-mapping`은 지원하지 않습니다. `--space`는 해당 스페이스 **홈페이지의 하위 트리**이며 홈페이지 밖의 별도 최상위 페이지까지 열거하는 기능은 아닙니다.

## 작업 범위 변경

```bash
csync init --base ./스페이스 --scope "지식자산/특허출원"
csync init --base ./스페이스 --scope "지식자산/특허출원/006_변리사_전달_문서.md"
csync init --base ./스페이스 --scope /
```

웹에서는 **01 문서 탐색** 트리에서 파일·폴더 이름을 선택한 뒤, 탐색 위 스코프 영역의 **선택한 범위를 스코프로 저장**을 누릅니다. 전체는 트리의 기준 폴더 이름을 직접 선택합니다. 스코프 저장은 원격 위치를 바꾸거나 기존 매핑을 삭제하지 않습니다. 파일 이동에 따른 원격 위치 변경은 별도의 명시적인 Push에서만 반영합니다.

## 파일 이동과 자동 매핑

로컬 문서의 `pageId`를 유지한 채 파일을 옮기고 `push`하면, 기존 매핑에서 같은 페이지를 찾아 새 경로와 부모 위치를 자동으로 계산합니다. 별도 `remap` 실행은 필요하지 않습니다. 웹 미리보기·동기화도 같은 동작을 사용합니다.

```bash
# 로컬 파일·폴더 정리 후
csync push --dry-run  # 이동·본문 변경 계획 확인, 매핑 저장 없음
csync push            # 원격 위치와 버전을 확인한 뒤 이동·갱신
```

같은 ID를 가진 파일이 둘이거나 이전 경로의 파일이 남아 있으면 중단합니다. 파일을 복사해서 새 페이지를 만들려면 복사본의 `pageId`를 제거하세요. 기존 페이지의 원격 버전 기준이 없으면 자동 이동도 차단하므로 로컬 편집을 보관하고 pull로 기준을 확보해야 합니다.

`remap`은 별도 매핑을 가져오거나 원격 호출 없이 매핑만 저장하려는 고급 작업에 남겨둡니다.

```bash
csync remap --dry-run
csync remap
csync remap --base ./정리본 --from-mapping ./원본/.csync/mapping.json
```

- 기존 ID·제목·해시는 보존하고, 현재 경로에 따른 부모를 `pendingMove.parentKey`에 기록합니다. push 시 실제 부모와 비교해 이동하고 성공 후 대기 기록을 제거합니다.
- 경로만 달라지고 렌더링 결과 해시가 같으면 본문·첨부 업로드 없이 이동합니다. 제목·본문·링크 변환 결과가 달라졌거나 기존 해시가 없으면 본문 갱신 대상이지만 원격 버전 기준이 없을 때는 차단합니다. `remap`은 새 해시를 만들어 변경을 숨기지 않습니다.
- 매핑에 없는 상위 폴더는 같은 스페이스·부모·제목의 원격 폴더를 먼저 찾아 연결하고, 없을 때만 push 시 생성합니다. 폴더의 부모는 로컬 계층과 기존 매핑·스페이스 루트를 기준으로 결정합니다. 그 외 이름만 같고 부모가 다른 폴더는 재사용하지 않고 위치 충돌을 표시합니다. 폴더 검색과 메타데이터 조회 권한이 필요합니다. 생성 중 동명 충돌(400) 또는 충돌(409)이 나면 한 번 재조회해 같은 위치의 폴더를 재사용합니다. 매핑의 기존 폴더도 스페이스·제목·부모를 검증하며, 권한 오류나 위치 충돌은 자동 생성·이동으로 우회하지 않습니다. README가 있는 디렉토리는 해당 README 페이지가 부모입니다. 루트의 일반 문서는 스페이스 루트 아래에 연결됩니다. 스코프 변경은 이동을 만들지 않으며 스페이스 홈페이지 자체는 이동할 수 없습니다.
- 동일 ID를 가진 여러 문서나 매핑, 경로의 ID 충돌, 손상된 JSON은 저장 전에 거부합니다. 이동 대상 페이지 조회 실패 시 자동 재생성하지 않으며, 이동 실패 시 대기 기록을 유지합니다.
- `--mapping`은 출력 매핑 위치, `--from-mapping`은 읽기 전용 원본 매핑입니다. `.csync/ignore`와 반복 `--exclude`를 지원합니다. 원본과 정리본을 함께 스캔하지 말고 정리본만 `--base`로 지정하세요.
- ID가 없는 문서는 remap에서 미연결로 표시합니다. **이후 sync에서는 기존 규칙대로 새 페이지가 생성될 수 있으므로**, 관리용 문서는 ignore로 제외하세요.
- 대상에 없는 기존 매핑은 유지합니다. 폴더 자체에는 frontmatter ID가 없으므로 폴더 ID의 경로 변경은 추론하지 않으며, 새 위치에는 새 폴더가 생성될 수 있습니다. 원격의 빈 폴더를 자동 삭제하지 않습니다.
- 부모 페이지 이동은 원격 하위 페이지에도 영향을 줄 수 있습니다. `--dry-run`은 로컬 계획이며 원격 상태를 조회하지 않습니다. sync는 실행 시점의 로컬 트리를 기준으로 이동 계획을 다시 계산합니다.

이동은 [Confluence의 페이지 이동 API](https://developer.atlassian.com/cloud/confluence/rest/v1/api-group-content---children-and-descendants/#api-wiki-rest-api-content-pageid-move-position-targetid-put)를 사용합니다.

## 빠른 시작

```bash
cd /path/to/docs          # 동기화할 .md 들이 있는 폴더

confluence-sync init      # 대화형으로 .env 생성 (토큰 입력은 가려짐)
confluence-sync init --base . --scope "지식자산/특허출원" # 필수: 원격 위치 직접 선택
confluence-sync push --dry-run # 무엇이 올라갈지 미리보기
confluence-sync push           # 실제 발행
```

반대로 Confluence에서 가져오려면:

```bash
confluence-sync pull                      # 미리 선택한 스코프만 .md 로
```

## 웹에서 변환·동기화하기

화면 상단의 **사용 도움말**에서 변환·동기화 순서, 참조 링크, 덮어쓰기와 로그 설명을 확인할 수 있습니다.

```bash
csync web                         # 홈 폴더에서 시작, 브라우저 자동 열기
csync web --base ~/Documents       # 원하는 폴더에서 시작
```

1. 01의 **기준 폴더 변경…**으로 시스템 폴더 다이얼로그를 열어 Vault나 문서 묶음의 기준 폴더를 지정합니다. **경로를 직접 입력해 변경**을 펼치고 **이 폴더를 기준으로 설정**을 눌러도 됩니다. 기준 폴더 카드에는 실제 적용된 이름과 전체 경로가 표시됩니다. 아래 **문서 탐색**은 상대 위치를 표시하며, 하위 폴더를 열어도 기준 폴더는 바뀌지 않습니다. **기준 폴더로** 버튼으로 돌아갈 수 있습니다.
2. 파일 이름을 검색하면 기준 폴더의 모든 하위 폴더에서 `.md` 문서를 찾고 상대 경로를 함께 표시합니다. 검색어를 지우면 현재 폴더 목록으로 돌아갑니다. 문서 트리에서 폴더 옆 화살표는 하위 항목을 펼치거나 접고, 폴더·파일 이름은 변환 대상을 선택합니다. 폴더 이름을 선택하면 하위 Markdown 전체, 파일 이름을 선택하면 그 문서 하나가 대상입니다. 펼침·접기는 선택한 대상을 바꾸지 않습니다.
3. **출력 폴더 선택…**으로 저장 위치를 지정합니다. 새 폴더 경로를 입력할 수도 있으며, 비워두면 기준 폴더 옆에 `폴더명-converted-XXXXXX`를 만듭니다.
4. **문서 미리보기**는 기본적으로 접혀 있습니다. `.md` 파일을 선택하고 **문서 미리보기 · 펼치기**를 누르면 본문이 표시됩니다. 접힌 동안에는 문서 렌더링 요청을 보내지 않습니다. HTML 표의 너비·병합 셀과 기준 폴더 안의 로컬 이미지도 표시하며, 내용을 선택해 복사할 수 있습니다. 파일을 외부에서 수정한 뒤에는 미리보기의 **새로고침**을 누르세요. 변환·동기화 탭 모두에서 사용할 수 있습니다.
5. **변환 미리보기**를 누르면 본문 비교 화면에 삭제·추가된 부분이 색상으로 표시됩니다. 나란히/인라인 비교와 이전·다음 변경 이동을 지원합니다.
6. **변환 후 저장**을 누르고 **결과 폴더 열기**로 확인합니다.

웹에서 파일 하나를 선택하면 출력 폴더 바로 아래에 저장합니다. 폴더 전체를 선택하면 모든 하위 Markdown을 변환하고, 선택한 폴더 내부의 상대 경로만 출력 폴더 아래에 유지합니다. 링크 해석 기준은 단일 파일의 부모 폴더 또는 선택한 폴더입니다. CLI의 `--base` 동작은 그대로입니다. 원본과 겹치는 출력 경로는 거부하며, 기존 출력 파일과 내용이 같으면 재사용하므로 같은 폴더에 연속 저장할 수 있습니다. 이름은 같지만 내용이 다르면 대상 파일 목록을 보여주고 덮어쓸지 확인합니다. 취소하면 저장하지 않으며, 확인한 기존 파일이 변경되면 다시 확인합니다. **다른 문서 선택**을 누르면 기준 폴더와 변환 설정을 유지한 채 다음 문서를 고를 수 있습니다. 선택한 대상의 문서와 참조 첨부를 내보냅니다. 단일 파일 모드에서는 링크로 참조된 다른 문서를 함께 복사하지 않습니다. 폴더 변환의 본문 비교는 최대 20개 문서(문서당 200KB 이하)를 선택해서 확인하며, 실제 저장은 전체 문서에 적용됩니다.

변환 미리보기는 원본 파일을 변경하지 않습니다. 폴더 선택창을 사용할 수 없는 환경에서는 경로를 직접 입력할 수 있습니다. Linux에서 폴더 선택창을 사용하려면 `zenity`가 필요합니다.

웹은 `http://localhost:4318` 또는 `http://127.0.0.1:4318`에서 열 수 있습니다. 두 주소의 브라우저 저장소는 별개이므로 기존 경로 설정을 유지하려면 같은 주소로 접속하세요. 변환과 동기화 미리보기는 Confluence 인증 없이 사용할 수 있습니다. 내 컴퓨터의 파일을 탐색하므로 개인용 로컬 실행을 전제로 합니다. `--port 4320`으로 포트를 바꾸거나 `--no-open`으로 자동 열기를 끌 수 있습니다. 종료는 터미널에서 `Ctrl+C`입니다.

변환 탭과 동기화 탭은 기준 폴더·탐색 위치·선택 문서를 각각 기억합니다. 예를 들어 변환은 Obsidian Vault를 기준으로 하고, 동기화는 변환 결과 폴더를 기준으로 지정할 수 있습니다. 각 탭의 경로와 출력 경로·작업 옵션은 같은 브라우저의 로컬 저장소에 보관되어 탭 전환과 새로고침 후에도 유지됩니다. 삭제되거나 열 수 없는 경로는 안내 후 선택을 해제하거나 시작 폴더로 돌아갑니다. 인증 토큰과 동기화 실행 승인은 저장하지 않습니다.

### 표 서식 편집

1. `.md` 파일을 선택하고 **문서 미리보기**를 펼친 뒤 **표 서식 편집**을 누릅니다.
2. 미리보기에서 표를 클릭합니다. 선택한 표의 강조선과 열 경계 손잡이가 표시됩니다.
3. **내용에 맞춤**을 누르면 셀의 글자 길이에 따라 짧은 열을 좁히고 긴 설명 열을 넓힙니다. 한글 등 넓은 문자와 병합 셀을 고려하고, 일부 긴 셀의 영향을 제한해 배분합니다. 전체 너비는 유지합니다. 경계를 드래그하여 미세 조정하거나 **균등 배분**으로 바꿀 수도 있습니다. **전체 너비** 슬라이더로 표 크기도 바꿀 수 있습니다.
4. **변경 비교**에서 원본·수정본을 확인한 뒤 **원본 파일에 저장**을 누릅니다. 여러 표를 수정했다면 함께 저장합니다.

저장 전 변경은 화면에만 적용됩니다. **변경 취소**는 선택한 표를 처음 상태로 되돌립니다. 파일을 바꾸거나 미리보기를 새로고침하면 미저장 변경은 취소됩니다. 외부에서 파일이 수정되었다면 덮어쓰지 않고 다시 읽도록 안내합니다.

일반 Markdown 표는 너비를 저장하기 위해 해당 표만 HTML로 변환합니다. 기존 HTML 표는 셀 내용과 `colspan`·`rowspan`을 보존하며, 문서의 나머지 부분은 유지합니다. 현재는 픽셀 너비를 저장하고 열당 최소 40px·전체 최대 3000px를 지원합니다. 중첩 표와 목록 안의 표 등 원본 위치를 안전하게 대응할 수 없는 표는 편집하지 않습니다. 일반적인 Prettier 소스 포맷팅은 포함하지 않습니다.

### Confluence: 업로드(Push)와 가져오기(Pull)

1. 왼쪽에서 기준 폴더를 열고 **Confluence** 탭을 선택합니다.
2. **01 문서 탐색**에서 화살표로 폴더를 펼치고, 파일·폴더 이름을 선택한 뒤 **선택한 범위를 스코프로 저장**을 누릅니다. 기준 폴더 이름을 선택하면 전체 `/`입니다. 선택·탐색만으로 저장된 스코프가 바뀌지는 않습니다.
3. **업로드(Push)**에서는 미리보기에서 선택 범위의 신규·변경·이동과 링크 경고를 확인한 뒤 업로드합니다. 원격 확인을 선택하면 미리보기에서도 읽기 전용으로 원격 버전을 확인합니다.
4. **가져오기(Pull)**에서는 저장된 작업 스코프의 문서만 원래 위치에 내려받습니다. 처음 빈 폴더에는 `/`로 전체 매핑을 확보해야 합니다. 로컬 변경·이동 대기가 있으면 중단합니다.

01에서 다른 파일을 미리보기해도 저장된 작업 스코프는 바뀌지 않습니다. 스코프를 저장해야 작업 범위에 반영됩니다. 기존 전체 매핑과 범위 밖 문서는 유지됩니다.

## Push — Markdown → Confluence

```bash
confluence-sync push --list                 # 인식된 문서·제목·계층만 출력 (호출·인증 없음)
confluence-sync push --dry-run              # 대상·상태(신규/변경/동일) 미리보기
confluence-sync push                        # 변경된 문서만 갱신 (+ 신규 생성)

confluence-sync push --base /abs/path/docs  # 동기화 루트 지정 (미지정 시 환경변수·상위 작업공간 탐색)
confluence-sync push guide/                 # 지정 폴더만
confluence-sync push guide/setup.md         # 단일 문서만 (상위 README 는 발행되지 않음)
confluence-sync push --force                # 변경 감지 무시, 전체 강제 갱신
confluence-sync push --verify               # 변경 없는 문서도 원격 버전·존재 확인
confluence-sync push --exclude '*-draft.md' # 제외 패턴 (반복 가능)
```

### 폴더 = 페이지 계층

- 폴더의 **`README.md`** 가 그 폴더의 **대표 페이지**가 되고, 같은 폴더의 다른 문서는 그 자식이 됩니다.
- README 가 **없는** 폴더는 **Confluence 폴더**로 생성되고 그 아래로 문서가 들어갑니다 (`write:folder` 스코프 필요).
- `README.md` 는 폴더 맨 앞, 나머지는 파일명순(숫자 prefix `01-`, `10-` … 로 순서 제어)으로 정렬되어 부모가 자식보다 먼저 생성됩니다.

> **경로를 지정해 동기화할 때**는 상위 `README.md` 가 **발행 대상이 아닙니다.** 자식을 붙일 부모 pageId 를 얻는 데만 쓰이고, 내용이 바뀌어 있어도 갱신하지 않습니다(`· 상위` 로 표시). 아직 페이지가 없으면 자식을 붙일 곳이 없으므로 그때는 생성합니다. 상위 문서도 갱신하려면 함께 지정하세요.

```
docs/                      → [스페이스 홈페이지]
├── README.md              → 루트 페이지
├── 10-guide/
│   ├── README.md          → "10-guide" 대표 페이지
│   └── 01-setup.md        → 그 자식 페이지
└── 20-notes/              → README 없음 → Confluence 폴더
    └── memo.md            → 폴더 안 페이지
```

### 변환 규칙

- 페이지 제목은 **frontmatter `title` → 첫 `# 제목` → 파일명** 순으로 정해지고, 본문은 storage format 으로 변환됩니다.
- 코드블록 → **code 매크로**, 표·리스트·헤딩은 그대로.
- `mermaid` 코드블록 뒤에는 **Mermaid diagram** 매크로를 자동 삽입합니다. Confluence에 [Atlassian Labs Mermaid Diagrams Viewer](https://marketplace.atlassian.com/apps/1232887/mermaid-diagrams-viewer)가 설치되어 있어야 하며, 원본 코드도 함께 표시됩니다. 자동 연결은 등장 순서를 사용하므로 페이지의 모든 Mermaid 코드는 `mermaid` 코드블록으로 작성하세요.
- **내부 `.md` 링크**와 **`[[wikilink]]`** → Confluence 페이지 링크로 자동 변환.
- **섹션 링크** `[§1 개요](#1-개요)` · `[§6](./04-구현체.md#6-zkp)` · `[[문서#헤딩 텍스트]]` → Confluence 앵커 링크. [아래 참조](#섹션-링크-앵커)
- **일반 파일 링크** `[자료](<attachments/자료.pdf>)` → PDF·TXT·MMD·JSON 등 실제 로컬 파일을 페이지 첨부로 업로드하고 다운로드 링크로 변환합니다. 경로는 Markdown 문서 위치 기준이며, 한글·공백 경로와 반복 링크를 지원합니다. 문서 링크(`.md`)·외부 URL·없는 파일은 기존 링크를 유지합니다. 같은 페이지에서 서로 다른 파일의 파일명이 같으면 업로드 이름에 경로 기반 접미사를 붙여 구분합니다.
- **로컬 이미지**와 **`![[embed]]`** → 페이지 첨부로 업로드 후 참조 (같은 파일명은 새 버전으로 갱신). 외부 URL 이미지는 그대로.
- **YAML frontmatter** 는 메타데이터로만 쓰이고 본문에 새지 않습니다.

### 표 너비 지정

일반 Markdown 표(`| … |`)에는 너비 문법이 없습니다. 짧은 번호·구분 열과 긴 설명 열의 너비를 다르게 지정하려면 `.md`에 HTML 표를 작성합니다. 전체 너비와 각 열 너비는 양의 픽셀 값으로 지정합니다.

```html
<table style="width: 760px;">
  <colgroup>
    <col style="width: 100px;" />
    <col style="width: 660px;" />
  </colgroup>
  <tbody>
    <tr><th>구분</th><th>설명</th></tr>
    <tr><td>특허</td><td><strong>상세 설명</strong></td></tr>
  </tbody>
</table>
```

- Push는 전체 너비를 Confluence의 `data-table-width`에, 열 너비를 `colgroup`에 반영합니다. 전체 너비를 생략하고 모든 열 너비를 지정하면 합계를 사용합니다.
- Pull은 원본 storage의 너비를 읽어 HTML 표로 보존합니다. `colspan`·`rowspan`이 지정된 표도 너비 지정 여부와 관계없이 HTML로 유지합니다. 너비와 병합 속성이 없는 표는 기존 GFM 표로 변환합니다. storage와 export_view의 표 개수가 다르면 storage 너비를 순서대로 적용하지 않고 export_view의 너비만 사용합니다.
- 셀 안에서는 `**굵게**`, `[링크](파일)` 대신 `<strong>굵게</strong>`, `<a href="파일">링크</a>`를 씁니다. HTML 표 안의 문서·섹션 링크와 로컬 첨부 링크·이미지도 Push에서 처리합니다. Pull의 HTML 셀 안 링크는 `--obsidian`에서도 HTML 링크로 유지합니다.
- 퍼센트 너비와 임의 CSS의 왕복 보존은 지원하지 않습니다. HTML·스타일 표시 여부는 Markdown 뷰어에 따라 다르며, Confluence 편집기의 실제 표시·재저장 결과는 별도 확인이 필요합니다.
- 웹의 **문서 미리보기**는 파일 선택 시 Markdown·HTML 표를 렌더링합니다. **변환 미리보기**는 원본과 변환 결과의 소스를 비교합니다. 문서 미리보기는 1MB 이하 문서를 지원하며, 표 서식은 변경 비교 후 명시적으로 저장할 수 있습니다. 로컬 이미지는 기준 폴더 안의 PNG·JPEG·GIF·WebP·AVIF(개당 5MB 이하)를 표시합니다. 외부 이미지와 문서에 포함된 스크립트는 실행하지 않으며 Confluence의 실제 화면·붙여넣기 결과와 다를 수 있습니다.

### 다른 동기화 폴더의 문서 링크

`--reference-root`를 반복해서 지정하면 다른 동기화 폴더에 이미 게시된 문서로 연결할 수 있습니다.

```bash
csync push --base ./confluence-docs/project \
  --reference-root ./confluence-docs/DBP \
  --reference-root ./confluence-docs/shared \
  ./confluence-docs/project/guide.md --dry-run
```

위키링크 `[[원본/긴/경로/문서명|표시 이름]]`와 Markdown 링크 `[표시 이름](../이전/문서명.md)` 모두 지원합니다. 현재 루트의 정확한 경로를 먼저 찾고, 참조 루트의 정확한 경로, 전체 후보의 파일명 순으로 검색합니다. 파일명 검색 결과가 하나일 때만 연결하며 별칭은 유지합니다. 현재 루트의 문서는 페이지 제목으로, 참조 문서는 `<참조 루트>/.csync/mapping.json`의 페이지 ID를 사용한 URL로 연결합니다.

참조 폴더는 같은 Confluence 서버의 문서여야 합니다. 참조 폴더의 `.env`에 서버 주소가 있으면 현재 서버와 일치하는지 검사합니다. `.env`가 없으면 현재 서버의 매핑으로 간주합니다. 참조 문서와 매핑은 읽기만 하며 함께 업로드하지 않습니다. 제외 규칙도 적용합니다. 페이지 ID의 실제 서버 존재 여부는 미리보기에서 검사하지 않습니다.

중복 파일명, 대상 문서 누락, 게시 매핑 누락은 CLI 출력과 웹 동기화 미리보기에 경고로 표시하고 링크 원문은 유지합니다. 경고는 업로드를 차단하지 않으므로 실행 전에 확인하세요. 다른 루트의 섹션 링크는 기존 앵커를 사용하며 참조 페이지에 앵커를 새로 만들지 않습니다.

웹에서는 **Confluence 동기화 → 참조 문서 폴더**에 한 줄씩 입력하거나 **참조 폴더 추가…**로 선택합니다. 설정은 새로고침 후에도 유지됩니다. 참조 폴더의 문서·매핑·설정이 변경되면 다시 미리보기해야 합니다. `convert`에는 이 옵션이 필요하지 않습니다.

### 섹션 링크 (앵커)

문서는 표준 마크다운 그대로 두면 됩니다. 이 도구가 Confluence 쪽 앵커를 만들어 맞춰 줍니다.

**Confluence 가 헤딩에 자동으로 붙이는 id 에는 기대지 않습니다.** 그 규칙은 Cloud 와 Data Center 가 다르고(Cloud 는 공백만 하이픈으로 바꾸고, DC 는 `페이지제목-헤딩` 형태) 예고 없이 바뀌기 때문입니다. 대신 **링크 대상이 되는 헤딩 앞에 [Anchor 매크로](https://confluence.atlassian.com/doc/anchors-139442.html)로 이름(= 마크다운 슬러그)을 직접 심고** 링크가 그 이름을 가리키게 합니다 — 양쪽 다 이 도구가 정한 값이라 어느 배포판에서도 맞습니다. 실제로 가리켜지는 헤딩에만 심으므로 페이지가 지저분해지지 않습니다.

| 쓰는 것 | Confluence 에서 |
| --- | --- |
| `[§1 개요](#1-개요)` | 같은 페이지의 그 헤딩으로 이동 |
| `[[#1. 개요]]` · `[[#1. 개요\|§1]]` | 위와 동일 (Obsidian 표기) |
| `[§6 ZKP](./04-구현체.md#6-zkp)` | 그 페이지의 그 헤딩으로 이동 |
| `[[04-구현체#6. ZKP]]` | 위와 동일 (Obsidian 표기) |

- 슬러그 규칙은 **GitHub 과 동일**합니다 — 소문자화 → 문자·숫자 아닌 것 제거 → 공백 하나당 하이픈 하나. 공백을 접지 않으므로 `제목  ·  블록` 의 `--` 도 그대로 맞습니다. 겹치는 헤딩에는 `-1`·`-2` 가 붙습니다.
- 문서의 첫 `# H1` 을 가리키는 링크는 **페이지 최상단**이 됩니다 (H1 은 Confluence 페이지 제목이 되므로).
- **대응하는 헤딩을 못 찾으면 링크를 바꾸지 않고 경고합니다.** 엉뚱한 섹션으로 보내는 대신 알려주는 쪽을 택했습니다 — 대개 오타나 깨진 상대경로입니다.

```
$ confluence-sync push --base ./docs --dry-run
  [변경] guide/usage.md  →  "사용 안내"  (…, 내부링크: 36, 섹션링크: 30, 앵커: 15, 이미지: 0)
  ⚠ 대응 헤딩 없는 앵커  guide/reference.md  #없는-헤딩
```

`섹션링크` 는 이 문서가 **가리키는** 링크 수, `앵커` 는 이 문서에 **심긴** 앵커 수입니다(다른 문서가 가리키는 것 포함).

pull 은 반대로 Confluence 앵커를 마크다운 슬러그로 되돌립니다(`--obsidian` 이면 `[[문서#헤딩 텍스트]]`).

### 변경 감지와 매핑

- 문서의 `제목 + 본문 + 참조 첨부 내용` 해시를 저장해두고, **바뀐 문서만** 새 버전으로 올립니다(실제 sync는 위치·원격 버전을 조회한 뒤 `= 변경없음`으로 처리). `--force` 로 무시할 수 있습니다.
- 매핑은 **`<base>/.csync/mapping.json`** 에 저장됩니다. **문서셋과 함께 커밋하세요** — 지우면 다음 실행에서 페이지가 중복 생성됩니다. (`--mapping <path>` 로 위치 변경 가능)
- **pull 도 같은 매핑에 기록합니다** — 그래서 pull 직후 push 하면 `= 변경없음` 입니다. [Pull → 매핑 기록](#매핑-기록) 참고.
- Confluence에서 페이지가 삭제됐거나 원격 버전이 달라졌다면 **중단하고 기존 매핑을 유지**합니다. 변경 없는 페이지까지 검사하려면 `--verify`를 사용합니다.

### 동기화 제외 (로컬 전용 문서 유지)

같은 폴더에 올릴 문서와 로컬에만 둘 문서가 섞여 있을 때 제외할 수 있습니다.

- **`<base>/.csync/ignore`** — `.gitignore` 방식 패턴 파일 (문서셋과 함께 커밋)

  ```gitignore
  *-draft.md            # 초안 전부 제외
  notes/local-only.md   # 특정 파일만 (notes/ 의 나머지는 동기화)
  secret/               # 폴더 통째로
  ```

- **`--exclude <glob>`** — 일회성 제외 (반복 가능)

제외된 문서는 list·dry-run·sync 모든 모드에서 빠지고, 그 문서만 있던 폴더는 생성되지 않습니다. 부정(`!`), `**` 등 `.gitignore` 규칙을 그대로 따릅니다.

### v1의 `--rebuild` 이전 안내

전체 삭제 후 재생성하던 `--rebuild`는 v2에서 제거되었습니다. 기존 페이지 ID를 유지하고, 파일을 옮긴 후 `push --dry-run`으로 확인해 `push`로 반영하세요. 본문을 강제로 다시 발행하려면 `push --force`를 사용합니다. 원격 충돌 검사는 유지되며 삭제·재생성하지 않습니다.

## Pull — Confluence → Markdown

```bash
# 먼저 작업 스코프를 직접 선택한 작업공간에서 실행
confluence-sync pull                    # 선택 스코프 전체를 로컬 루트에
confluence-sync pull --obsidian         # 내부 링크를 위키링크로
confluence-sync pull <mapped-page-id>   # 이미 매핑된 하위 페이지 하나
confluence-sync pull --space            # / 스코프를 직접 선택한 경우에만 가능
```

- 대상을 생략하면 저장된 스코프를 재귀 복원합니다. 페이지 스코프 본문은 루트 `README.md`이고 폴더 스코프는 본문 없이 자식을 받습니다.
- 숫자 ID나 URL로 하위 항목을 지정할 때도 스코프 안인지 검증하며 기존 매핑 경로를 사용합니다. 매핑 없는 하위 항목은 먼저 스코프 전체를 pull해 경로를 확보하세요.
- `pull`은 지정한 대상과 하위 페이지·폴더를 항상 함께 가져옵니다. `--children`은 필요하지 않습니다. 기존 스크립트의 `--children`은 호환을 위해 그대로 허용합니다.
- 출력 루트를 바꾸려면 그 로컬 폴더에 스코프부터 설정합니다. 로컬 문서 루트의 `--base`와 `--out`은 같아야 합니다. 범위가 없을 때 현재 폴더나 전체 스페이스로 대신 실행하지 않습니다.
- **누락된 원격 첨부**: 페이지의 첨부 목록에 없거나 다운로드가 404이면 원격 URL 참조를 유지하고 나머지 문서는 계속 가져옵니다. 로그에 페이지 ID·파일명과 누락 개수를 남기며 웹에는 **완료(경고)**로 표시합니다. 로그인·권한 오류(401/403), 네트워크·서버 오류는 누락으로 처리하지 않고 Pull을 중단합니다.
- **이미지/첨부** 는 문서별로 `attachments/<문서명>/` 아래에 내려받고 링크를 그 경로로 씁니다 (문서 폴더가 이미지로 지저분해지지 않음). 다운로드에는 `read:attachment` 스코프가 필요합니다.
- **내부 링크** 는 같은 실행에서 함께 받은 페이지끼리 **상대 `.md` 링크로 이어집니다.** 받지 않은 페이지는 절대 URL 로 남습니다(깨진 링크를 만들지 않음).
- **섹션 링크** 는 Confluence 앵커(`#페이지제목헤딩텍스트`)를 그 문서의 **마크다운 슬러그로 되돌립니다** — 그대로 두면 Obsidian·GitHub 어디서도 걸리지 않기 때문입니다. `--obsidian` 이면 `[[문서#헤딩 텍스트]]` 로 씁니다.
- 각 문서 머리에 **frontmatter** 가 붙습니다 — `title` · `pageId` · `spaceKey` · `source` · `updated`. `pageId` 가 다시 push 할 때의 앵커입니다.
- 제목은 frontmatter 의 `title` 로만 들어가고 **본문에 `# 제목` 을 따로 넣지 않습니다** — 제목을 별도로 표시하는 뷰어(Obsidian 등)에서 두 번 보이기 때문입니다. push 는 `title` 을 먼저 읽으므로 왕복에 문제가 없습니다.
- 본문은 `export_view`(HTML)를 [turndown](https://github.com/mixmark-io/turndown) 으로 변환합니다 — 코드블록(언어 포함, 미지정은 `plaintext`), GFM 표, 리스트 등.

> **무손실 왕복은 아닙니다.** Confluence storage → Markdown 은 근사 변환이라 일부 매크로·레이아웃은 단순화됩니다.

### 매핑 기록

pull 은 받아온 문서를 **매핑 파일에 함께 기록합니다** — 페이지 id 와, push 가 계산하는 것과 **같은 방식의 변경 해시**를 남깁니다. 그래서 **pull 직후 push 하면 `= 변경없음`** 입니다. 이게 없으면 매핑에 해시가 없어 방금 받아온 내용을 그대로 되올려 보내게 됩니다.

```bash
$ confluence-sync pull --base ./docs
  …
완료  페이지 42개, 폴더 3개 생성  내부링크 88개 연결  매핑 45건
  매핑: /repo/docs/.csync/mapping.json  (base: /repo/docs)

$ confluence-sync push --base ./docs --dry-run
  [동일] …          # 되올려 보낼 것이 없다
```

- **base 는 `--out` 에서 위로 올라가며 `.csync/mapping.json` 을 찾아 정합니다.** 매핑 키는 base 기준 상대경로여야 이어지는 push 가 같은 문서를 알아보기 때문입니다. 하위 폴더로 받아도(`--out <base>/일부`) 루트의 매핑에 제대로 들어갑니다.
- 작업공간을 찾지 못하거나 스코프가 없으면 초기화를 요구합니다. 설정 없이 pull로 루트 연결을 추측하지 않습니다.
- **`--base <dir>`** · **`--mapping <path>`**로 위치를 직접 지정할 수 있지만 유효한 작업공간 스코프는 항상 필요합니다. `--no-mapping`은 지원하지 않습니다.
- 같은 페이지가 다른 키에 남아 있으면(문서를 옮겼으면) 옛 키를 걷어내 중복 항목을 만들지 않습니다.

## Obsidian

pull 이 만드는 마크다운은 **vault 에 그대로 열립니다.** 별도 플러그인이 필요 없습니다.

```bash
cd ~/MyVault
confluence-sync init --base . --scope /          # 전체를 직접 선택
confluence-sync pull --obsidian                  # 선택한 스코프를 vault로
```

- 내부 링크가 이어져 있어 **그래프 뷰·백링크가 그대로 동작**합니다. 기본값인 상대 `.md` 링크도 Obsidian 에서 정상 동작하며 GitHub·VS Code 에서도 열립니다. vault 안에서만 쓸 거라면 `--obsidian` 으로 `[[wikilink]]` 를 받으세요.
- frontmatter 는 Obsidian 속성 패널에 표시되고, `source` 로 원본 페이지를 바로 열 수 있습니다.

## `convert` — 이미 받아둔 문서 손보기

**다시 pull 하지 않고** 로컬 `.md` 트리를 제자리에서 고칩니다. Confluence 를 호출하지 않으니 인증도 필요 없습니다.

```bash
confluence-sync convert --to obsidian ./docs            # 상대 .md 링크 → [[wikilink]]
confluence-sync convert --to markdown ./docs            # 되돌리기
confluence-sync convert --fix ./docs                    # 옛 pull 결과 보정
confluence-sync convert --to obsidian --fix ./docs      # 둘 다
confluence-sync convert --fix ./docs --dry-run          # 바뀔 파일만 미리보기
```

### 대상 지정

파일·폴더를 **여러 개** 줄 수 있고, 안 주면 base 전체가 대상입니다.

```bash
confluence-sync convert --fix ./docs/가이드/설치.md          # 파일 하나만
confluence-sync convert --fix ./docs/a.md ./docs/나머지/     # 파일 + 폴더 혼합
```

`--base` 는 **링크를 해석하는 범위**입니다. 파일 하나만 고칠 때도 주변 문서를 알아야 이름이 유일한지, 링크 대상이 실재하는지 판정할 수 있기 때문입니다. 지정하지 않으면 준 경로들의 공통 상위 폴더가 되며, `--to` 로 링크를 바꿀 때는 **문서 트리 루트를 `--base` 로 알려주는 편이 정확합니다.**

```bash
confluence-sync convert --to obsidian ./docs/가이드/설치.md --base ./docs
```

### 다른 곳에 내보내기 — `--out`

`--out` 없이 실행하면 **원본을 덮어씁니다.** 원본을 그대로 두고 결과만 따로 받으려면:

```bash
confluence-sync convert --to obsidian --fix ./docs --out ~/MyVault
```

- 문서는 base 기준 상대 경로를 재현하고, 첨부는 Pull과 동일하게 **각 문서 폴더의 `attachments/<문서명>/`**에 복사합니다. 예를 들어 `가이드/설치.md`의 첨부는 `가이드/attachments/설치/`에 저장합니다. 링크도 새 상대 경로로 바꾸며, PDF 원본과 페이지 이미지·HTML 표 안의 첨부에도 적용됩니다. 같은 문서 안의 동명 파일은 내용이 다르면 파일명에 구분값을 붙입니다. 기존 원본 문서와 첨부는 이동·삭제하지 않습니다.
- 안 바뀐 문서도 함께 내보내 **온전한 트리**가 나옵니다.
- `--out` 이 base 안이면 원본을 오염시키므로 거부합니다.

### 링크 표기 (`--to`)

두 방향은 서로의 역변환이라 **왕복해도 내용이 보존됩니다.** 안전하게 바꿀 수 있는 링크만 건드립니다.

- 외부 URL·이미지·깨진 링크(대상 파일 없음)는 **그대로 둡니다.**
- 파일명이 트리 안에서 겹치면(`README.md` 여러 개 등) `[[wikilink]]` 로 바꾸지 않고 상대 링크를 유지합니다 — 이름만으로는 어느 노트인지 확정할 수 없기 때문입니다.
- 코드블록·인라인 코드 안의 링크는 손대지 않습니다.
- **섹션 링크는 표기가 다릅니다** — 표준 마크다운은 슬러그(`문서.md#6-zkp`), Obsidian 은 헤딩 텍스트(`[[문서#6. ZKP]]`)를 씁니다. 대상 문서의 헤딩을 찾아 옮기고, 못 찾으면 섹션 없이 문서 링크로 둡니다. Obsidian 블록 참조(`#^id`)는 마크다운에 대응물이 없어 같은 방식으로 처리합니다.
- **같은 문서 섹션**도 마찬가지입니다 — `[§4](#4-버전)` ↔ `[[#4. 버전|§4]]`. 표 안에서 `\|` 로 이스케이프된 별칭도 인식합니다.

### 각주와 첨부

`--to markdown`은 각주를 위첨자 링크와 작은 제목으로 변환하고, 각주에 연결된 PDF의
`#page=N` 페이지를 이미지로 표시합니다. 첨부파일은 `attachments/`에 모아 연결합니다.
PDF 이미지 추출은 패키지에 포함된 PDF.js로 처리하므로 별도 도구 설치가 필요 없습니다.

`--to obsidian`은 변환 정보와 원본 PDF가 남아 있는 로컬 변환본에서 각주와 PDF 참조를 복원합니다.
Confluence에서 다시 내려받은 문서의 복원은 보장하지 않습니다.

### 보정 (`--fix`)

변환기가 개선되기 전에 pull 한 문서에는 옛 결함의 흔적이 남아 있습니다. 스페이스를 통째로 다시 받지 않고 그 흔적만 되돌립니다.

| 증상 | 보정 |
| --- | --- |
| frontmatter `title` 과 본문 `# 제목` 이 중복 | 겹치는 H1 제거 (Obsidian 에서 제목이 두 번 보임) |
| 모든 코드블록이 ` ```java ` | 실제 Java 가 아니면 `plaintext` 로 (Confluence 가 언어 미지정 시 `brush: java` 를 붙이는 탓) |
| 제목에 `[data-colorid=…]{color:#…}` | 본문에 새어 나온 CSS 제거 |
| `:11\_eleven\_blue:` · `\[선택 가능\]` · `**7️⃣**\-**1️⃣**` | 불필요한 `\` 이스케이프 해제 |
| 리스트 항목마다 빈 줄 | 같은 종류 항목끼리 붙임 (번호↔글머리 경계는 유지) |
| 코드블록 안 줄 끝 공백 | 정리 |

**멱등적입니다** — 두 번 돌려도 더 바뀌지 않고, 최신 pull 결과에는 아무것도 하지 않습니다. 애매하면 손대지 않는 쪽을 택하므로 진짜 Java 코드블록은 그대로 남습니다. 파일을 덮어쓰니 `--dry-run` 으로 먼저 확인하세요.

반대로 **vault 를 그대로 push** 할 수 있습니다. Obsidian 문법을 그대로 이해합니다.

| vault 에서 쓴 것 | Confluence 에 올라가는 것 |
| --- | --- |
| `[[설계]]` · `[[구조/설계\|설계 문서]]` | 페이지 링크 (짧은 이름·경로 모두 인식) |
| `[[설계#3. 구성]]` | 그 페이지의 그 섹션 |
| `[[#3. 구성]]` · `[[#3. 구성\|§3]]` | **같은 페이지**의 그 섹션 |
| `![[diagram.png]]` | 첨부 이미지 |
| frontmatter `title:` | 페이지 제목 |
| frontmatter `pageId:` | **그 페이지를 갱신** (새로 만들지 않음) |

- 코드블록·인라인 코드 안의 `[[...]]` 는 건드리지 않고, **대상을 못 찾은 링크는 원문 그대로** 둡니다(조용히 사라지지 않습니다).
- `.obsidian/` `.trash/` 등 숨김 폴더는 동기화 대상에서 제외됩니다.
- `pageId`가 있으면 매핑을 잃어버려도 새 페이지를 조용히 만들지 않습니다. 원격 버전 기준이 없으므로 갱신은 차단하며 pull로 기준을 다시 확보해야 합니다.

> pull → 편집 → push 왕복이 목적이라면 frontmatter 를 지우지 마세요. `pageId` 가 원본 페이지를 가리키는 유일한 단서입니다.
